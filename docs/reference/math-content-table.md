### Reading notes

- **Two notions of degree.** JacoPy has two separate gradings. *Operator degree* (`degree_of`): $|d|=1$, $|\iota_X|=-1$, $|\mathcal L_X|=0$, a vector field (as a derivation) 0. *Exterior degree* (`exterior_degree`): function 0, $p$-form $p$, $p$-vector $p$, vector field 1. Each row states which one is meant. $|a|$ is the degree of $a$.
- **Koszul sign.** When two elements of degrees $|a|$, $|b|$ are interchanged, the sign $(-1)^{|a||b|}$ appears.
- **Conventions fixed in the code.**
  - Wedge determinant convention: $(\alpha\wedge\beta)(X,Y)=\alpha(X)\beta(Y)-\alpha(Y)\beta(X)$ (no $1/p!$).
  - $d$ is defined by the Palais formula, without a combinatorial prefactor.
  - $\iota_X$ puts $X$ into the **first** slot.
  - (Anti)symmetrization $\mathrm{Sym}/\mathrm{Alt}$ is normalized by $1/k!$.
- **General principle (central).** Every object is defined over a vector bundle $E$; taking $E=TM$, $\rho=\mathrm{id}$, $[\cdot,\cdot]_E=[\cdot,\cdot]_{\mathrm{Lie}}$, the algebroid version reduces to the ordinary version.
- **`*Definition` / `*Declaration` / `prove_*`.**
  - A `*Definition` class is a *rewrite rule* (left-hand side → right-hand side): it applies a definition or a linearity property that follows directly from a definition. Some are "THEOREM-classified": they use a proved theorem as a rule.
  - A `*Declaration` class is an axiom **explicitly declared** by the user (e.g. $[\pi,\pi]_{SN}=0$, the fundamental identity, $d\omega=0$, $d_\theta R=0$); none is assumed silently. "Under declaration" = closes only once the corresponding declaration is registered; "undeclared" = no additional axiom is needed.
  - A `prove_*` function is a *theorem builder*: it reduces both sides to the same normal form with rules coming from the definitions and the declared axioms, and returns a step-by-step proof chain. The proofs are symbolic and instance-level (generic sections, concrete $p$).
- **"(according to the docstring)"** marker: the claim rests only on the file's docstring and was not traced separately in the code.
- **Source column.** In the packages (`packages/`), the citations were taken from the files' docstrings. In the `central/` rows, the bracketed citations in the content text ([MC …], [B …], etc.) were collected. In the core layers, the source column is "—" (citations, if any, are in the content text). Equation numbers were not re-checked against the papers on this page; full references are in the [bibliography](bibliography.md).

## jacopy/core/

This folder contains the **carrier structure** of the symbolic mathematics. The nodes of the expression tree live here: sum, (noncommutative) product, negation, power, rational number, $\wedge$, $\otimes$, Hodge $\star$, the duality pairing $\langle\alpha,X\rangle$, multilinear evaluation $\omega(Y_1,\dots,Y_p)$, the indexed sum $\Sigma_d$, and the symmetrization/antisymmetrization operations. Alongside these are the **symbolic degree algebra** as polynomials with $\mathbb Z$ coefficients, the registry that attaches **properties** such as "scalar", "graded", "graded-antisymmetric", "closed form", and "Poisson" to objects, and pattern matching (wildcards). The nodes are deliberately **inert**: sign rules, the Leibniz rule, and the axioms are applied not here but in the `algorithms/` and `central/` layers.

```{tip} Where to look
- Where is the $\wedge$ node defined? → `core/wedge.py`
- Evaluation $\omega(Y_1,\dots,Y_p)$ and the alternating property? → `core/multi_eval.py`
- The pairing $\langle\alpha,X\rangle$? → `core/pairing.py`
- Symbolic degree and the parity of the Koszul sign? → `core/symbolic_degree.py` (`Degree.parity`)
- Declarations "x is a scalar", "π is Poisson", "ω is closed"? → `core/properties.py` + `core/registry.py`
- $\sum_a$ (sum over a frame index)? → `core/indexed_sum.py`
```

## jacopy/algebra/

This folder contains the tools for **graded derivations** and the **graded commutator**. The application $D(x)$ of an operator to an argument, operator composition, $[A,B]=AB-(-1)^{\lvert A\rvert\lvert B\rvert}BA$, and the Lie bracket $[X,Y]$ of vector fields are here. Both gradings are defined here: the operator degree (`degree_of`) and the exterior algebra degree (`exterior_degree`). The Leibniz expansion itself is in `algorithms/product_rule.py`.

```{tip} Where to look
- Graded derivation and the application $D(x)$? → `algebra/derivation.py` (`Derivation`, `Act`)
- Graded commutator $[A,B]=AB-(-1)^{\lvert A\rvert\lvert B\rvert}BA$? → `algebra/commutator.py`
- Lie bracket $[X,Y]$ of vector fields? → `algebra/lie_bracket_vf.py`
- Exterior degree of a form / multivector? → `algebra/grading.py` (`exterior_degree`)
- Operator degree ($\lvert d\rvert=1$, $\lvert\iota_X\rvert=-1$)? → `algebra/derivation.py` (`degree_of`)
```

(mct-jacopy-algorithms)=
## jacopy/algorithms/

This folder contains the transformations used for the **algebraic normal form** of expressions: associativity, distributivity, collecting like terms, folding numerical coefficients, **graded-commutative sorting** with Koszul signs, sorting alternating multilinear evaluations, and the graded **Leibniz (product) rule**. All of these steps can be read as reducing an expression to a chosen representative of its equivalence class. At every step, which rules are permitted is defined explicitly: in a noncommutative product the order is preserved, and a sign is folded only if the degrees are known.

```{tip} Where to look
- Where is the graded Leibniz rule $D(ab)=D(a)b\pm aD(b)$ applied? → `algorithms/product_rule.py`
- Koszul sign rule (interchange of factors)? → `algorithms/sort_product.py`
- The cancellation $\omega(X,Y)+\omega(Y,X)=0$? → `algorithms/normalize_alternating.py`
- Full simplification pipeline? → `algorithms/simplify.py`
- Collecting like terms / factoring out a common factor? → `algorithms/collect_terms.py`, `algorithms/factor_terms.py`
- Pattern → right-hand side rewrite rules? → `algorithms/rewrite.py`
```

## jacopy/brackets/

This folder contains the **graded bracket** abstraction and the **derived bracket** construction. ## jacopy/central/objects/

This folder contains the **basic objects** of differential geometry. All of them are attached to a bundle $E$ (default $TM$):
- functions $C^\infty(M)$, vector fields and sections $\Gamma(E)$;
- $p$-forms $\Gamma(\Lambda^pE^*)$, $p$-vectors $\Gamma(\Lambda^pE)$, $(q,r)$-tensors;

- interior products $\iota_X$, $\tilde\iota_\omega$, $\iota_P$; musical isomorphisms $\sharp/\flat$;
- partial evaluation of multilinear maps.

This layer mostly sets up **the objects and the degree/type algebra** ($\deg\iota_X=-1$, $\nabla_X$ preserves type, etc.). The calculus rules are largely in `calculus/` and `tangent/`. (mct-jacopy-central-calculus)=
## jacopy/central/calculus/

This folder contains the tools of **the general Cartan calculus derived from an (anchor, bracket) pair**. `BracketCalculus` takes a pair $(\rho,[\cdot,\cdot])$:
- it defines the operator $d$ by the intrinsic Palais formula;
- it defines the operator $\mathcal L_X$ by core cases and an evaluation formula;
- everything else, such as $d^2=0$ and the Cartan formula, is proved as a **theorem** from these definitions.

The TM case $(\mathrm{id},\mathrm{Lie})$, the algebroid case $(\rho_E,[\cdot,\cdot]_E)$, and the Poisson case $(\pi^\sharp,\mathrm{Koszul})$ are instantiated through the same code. The rest of the folder consists of calculus-independent definition rules: placement of $\iota$ into slots, multilinearity, the determinant evaluation of the wedge, the expansion of Sym/Alt, indexed sums, partial evaluation, $\mathcal L$ and $\nabla$ on tensors. There is no `prove_*` in this folder.

```{tip} Where to look
- The definition of $\mathcal L_X$ ($\mathcal L_Xf$, $\mathcal L_XY=[X,Y]$, evaluation formula)? → `calculus/bracket_calculus.py` (`IntrinsicLDefinition`)
- How is the same $d$ shared between TM / algebroid / Poisson? → `calculus/bracket_calculus.py` (`BracketCalculus`; flags `skew`, `right_leibniz`)
- The evaluation convention of wedge (determinant)? → `calculus/indexed_rules.py` (`WedgeEvalDefinition`)
```

## jacopy/central/tangent/

This folder contains the tools of **the $TM$ case**:
- The Lie bracket, defined as a commutator.
- $d$ and $\mathcal L$, instantiated by the general calculus $(\mathrm{id},[\cdot,\cdot]_{\mathrm{Lie}})$.
- The anholonomy coefficients $\gamma^c_{ab}$ of a frame.
- The Schouten–Nijenhuis bracket.
- The Cartan relations.

Antisymmetry, Jacobi, Leibniz, the Cartan formula, $[\mathcal L,d]=0$, $[\mathcal L,\iota]=\iota_{[\cdot,\cdot]}$, $d^2=0$, and the like are **theorems proved from the definitions**; they are not added as axioms. Residuals of bracket identities (Jacobi) are closed by a "repair loop": the residual is proved separately on a generic function and then cited. The explicit `prove_*` functions in this folder prove $d^2=0$ and the Cartan formula for **0- and 1-forms**. Higher degrees: for $p=1,\dots,5$ each degree is a separate concrete proof (tests: `TestTMHigherDegrees::test_magic` and `::test_d_squared_zero`; on the algebroid side only the Cartan formula, `TestAlgebroidHigherDegrees`). There is no proof for symbolic (general) $p$, and within central there is no separate `prove_*` for $p\ge2$ either.

```{tip} Where to look
- The proof of $d^2=0$? → on functions `tangent/exterior.py` (`prove_d_squared_zero_on_functions`), on 1-forms `tangent/cartan.py` (`prove_d_squared_zero_on_one_forms`). $p=1,\dots,5$: each degree a separate concrete proof, test `tests/test_higher_degree_audit.py`; no proof for symbolic $p$.
```

## jacopy/central/algebroid/

This folder contains the tools of **the algebroid case**.
- The basic structure is an anchored bundle $(E,\rho)$: $\rho$ is a $C^\infty$-linear anchor, $u(f):=\rho(u)f$, and the coboundary $D=\rho^*\circ d$ is defined.
- The bracket is only $\mathbb R$-bilinear and opaque.
- The hierarchy axioms are *declared*: right/left-Leibniz, anchor morphism, Leibniz–Jacobi, antisymmetry, metric invariance, symmetric part. Levels: almost-Leibniz, local, pre-Leibniz, Leibniz, Lie, almost-Courant, metric, pre-Courant, Courant.
- The defect operators are defined: Jacobiator, Derivator, Predator.
- The locality projector is defined.
- The algebroid Cartan calculus is built with $(\rho_E,[\cdot,\cdot]_E)$.
- Theorems between axioms are proved, e.g. "right-Leibniz + Jacobi ⇒ anchor morphism".

Sources: B = arXiv:2210.00548, MC = arXiv:2006.05957; for the defect formulas TW = arXiv:2409.11973 App. A.

## jacopy/packages/metric_affine/

This package contains the metric-affine geometry tools. On the tangent bundle (TM) it provides the connection $\nabla$, torsion $T$, curvature $R$, and non-metricity $Q=\nabla g$, together with their tensoriality, Bianchi I/II (form with torsion), the Ricci identity, the generalized Koszul formula (Schouten decomposition), existence and uniqueness of the Levi-Civita connection, and frame components ($\Gamma^a_{bc}$, Cartan structure equations, Ricci, Ricci scalar, Einstein). The same framework is carried over to an algebroid $E$: the E-connection, pseudo-torsion/curvature, the torsion $^{L}T$ modified by the locality operator $L$ and the projected curvature $^{L}\hat R$, admissible connections, the derived algebroid $E^\nabla$ and the two exterior derivatives $d(\nabla)$, $\hat d(\nabla)$, the E-Koszul formula, and the E-Bianchi and E-Cartan equations. Main sources: MC (2020) and ADM (2023).

```{tip} Where to look
- Where are the definition and tensoriality of torsion and curvature? → `torsion_curvature.py` (`prove_torsion_tensorial`, `prove_curvature_tensorial`).
- Where are the Koszul formula and uniqueness of Levi-Civita? → `metric_koszul.py` (`prove_koszul_formula`, `prove_levi_civita_unique`); algebroid version: `e_koszul.py`.
- Where are Bianchi I/II with torsion proved? → `bianchi.py`; algebroid (E-Bianchi) version: `e_bianchi.py`.
- Where are the Cartan structure equations and the Ricci/Einstein components? → `frame_components.py`; algebroid version: `e_cartan.py`.
- Where are the locality-corrected torsion $^{L}T$ and the projected curvature $^{L}\hat R$? → `modified.py`.
- Where is the equivalence admissible connection ⟺ metric compatibility (almost-Courant)? → `admissible.py`.
```

## jacopy/packages/poisson/

This package contains the symplectic, Poisson, and Nambu–Poisson tools: the Poisson bracket $\{f,g\}=\pi(df,dg)$ defined by the Poisson bivector $\pi$, the Hamiltonian vector field, and the sharp map $\pi^\sharp$; the Koszul bracket $[\alpha,\beta]_\pi$ on 1-forms and the cotangent Lie algebroid $(T^*M,\pi^\sharp,[\cdot,\cdot]_\pi)$; the Jacobi identities under the declaration $[\pi,\pi]_{SN}=0$ (including Koszul–Jacobi on general 1-forms); the symplectic form $\omega$ and the bridge $\pi=\omega^{-1}$; the tilde calculus $(\tilde d,\tilde{\mathcal L},\tilde\iota)$ with the roles interchanged; and the Nambu–Poisson $(p+1)$-vector with the higher Koszul bracket. Jacobi-type identities are always proved under the declaration $[\pi,\pi]_{SN}=0$ (or the fundamental identity).

```{tip} Where to look
- Where are the definition, antisymmetry and Leibniz rule of the Poisson bracket? → `core.py`.
- Where is the Jacobi identity of the Poisson bracket proved? → `showcase.py` (`prove_poisson_jacobi`, under the declaration $[\pi,\pi]_{SN}=0$).
- Where is the Jacobi identity of the Koszul bracket on general 1-forms? → `koszul_jacobi.py` (`prove_general_koszul_jacobi`).
- Where are the symplectic form and the preservation of $\omega$ by the Hamiltonian flow? → `symplectic.py`.
- Where are the tilde calculus ($\tilde d$, $\tilde{\mathcal L}$, $\tilde\iota$) and $\tilde d^2=0$? → `tilde.py`.
- Where are the Nambu–Poisson structure and the higher Koszul bracket? → `nambu.py`.
```

## jacopy/packages/drinfeld/

This package contains the tools for calculus on algebroids and for Drinfel'd doubles. It contains: the calculus $(\mathcal L,\iota,d)$ induced on $Z$ by an algebroid $A$, and the second action $\mathcal K_V=-\mathcal L_V+d\iota_V$; the bialgebroid compatibility conditions; the double bracket on $E=A\oplus Z$ (standard double = Dorfman bracket, Poisson/LWX double, Nambu double); metric invariance; and the fact that the anchor is a bracket morphism. Main sources: DD (2024) and TW (2025).

## jacopy/packages/generalized/

This package contains the tools for generalized geometry and Courant algebroids: the LWX Courant axioms [C1]–[C5] and Uchino's redundancy theorems (some axioms follow from the others) and the alternative axioms [C'1]–[C'5] in Dorfman/Roytenberg form; the standard and H-twisted Dorfman/Courant brackets on $TM\oplus T^*M$ and their axiom sets; Poisson-generalized $(TM)_0\oplus(T^*M)_\theta$ and R-flux; identification of Courant structures from the Roytenberg bracket; (pre-)Bourbaki algebroids with an R-valued metric, Bourbaki pre-calculus, exact structures and the Ševera-type classification; transport of properties by a general $\Psi$-twist; and the exceptional double and the $\Psi_\Pi$ rotation. Sources: U, LWX, Roy, B (2022), AMSW, TW, MC, E6 paper (reference to be verified).

This folder contains the tools of the layer in which the user writes **their own research question**: generalized sections $U\oplus\omega_2\oplus\omega_5$ ($TM\oplus\Lambda^pT^*M$, the E₆ exceptional bundle $TM\oplus\Lambda^2\oplus\Lambda^5$), block-operator matrices for bundle automorphisms and their unipotent inverses, a Courant-type axiom suite (right Leibniz, symmetric part, anchor morphism, metric invariance, Leibniz–Jacobi), transport of the whole structure by a $\Psi$-twist, and index antisymmetrization $T^{[a_1\dots a_n]}$. (mct-jacopy-proof)=
## jacopy/proof/

This folder contains the tools for the notion of **proof**. An equality claim $\text{lhs}=\text{rhs}$ is brought to normal form by applying rules (definition/axiom/theorem) step by step; each step is recorded as "before → after". The axioms and hypotheses relied on, the structure (algebroid, Poisson structure…) they belong to, and the generality level of the result (every degree, or the $p=2$ instance) are tracked separately. The principles of mathematical proof are here too: "two derivations that agree on generators are equal", "the derived bracket theorem", the use of theorems by citation, and alternative rule orders in proof search. A residual is never counted as a refutation.

```{tip} Where to look
- How is an equality proved (general entry point)? → `proof/verifier.py` (`show_equal`, `prove_jacobi`)
- The principle "derivations that agree on generators are equal"? → `proof/strategies.py` (`AgreementOnGenerators`)
- Jacobi via the derived bracket theorem? → `proof/strategies.py` (`DerivedBracketStrategy`)
- Recording a proved theorem and using it in another proof (citation)? → `proof/theorems.py`
- Which assumptions does the result rest on? → `proof/result.py` (`requires`), `proof/registry_facts.py`, `proof/ownership.py`
- The engine that applies definition/axiom rules? → `proof/expansion.py`
```

(mct-jacopy-oracle)=
## jacopy/oracle/

This folder contains a **numerical falsifier independent of the engine**. When the engine closes an equality, both sides are evaluated in random concrete coordinate models and compared. Models: polynomial functions with $\mathbb Q$ coefficients on $\mathbb R^n$, vector fields, forms, multivectors; Poisson bivectors; algebroids $E=\mathbb R^n\times\mathbb R^r$. The library's definitions are **rewritten** here in coordinates: Palais $d$, interior product into the first slot, Schouten, Koszul, $\tilde d$, Nambu $\sharp$… An "AGREE" result is not a proof; it only means "not refuted in N models". The models also check numerically that they satisfy the axioms they claim.

```{tip} Where to look
- Numerical testing of an equality? → `oracle/check.py` (`check_equal`, `check_chain`)
- Coordinate formulas for $d$, $\iota$, $\mathcal L$, Schouten, Koszul? → `oracle/values.py`
- Algebroid models and which axioms they satisfy? → `oracle/models/algebroid.py`
- Poisson bivector models? → `oracle/models/tangent.py`
- Concrete computation of $d_E$ (Palais), Jacobiator, Derivator, Predator? → `oracle/realize_e.py`
- Testing that an unused assumption is really unnecessary? → `oracle/select.py`
```

## Appendix: open points

Points noticed while compiling this table that are not yet resolved:

1. **The Predator is used with two signs.** In `jacopy/central/algebroid/operators.py`, $P_\Phi(u,v)=\Phi[u,v]-[\Phi u,\Phi v]$; in `jacopy/central/algebroid/defect_formulas.py`, the defect is defined with the opposite sign, following the convention of TW Appendix A. The code is internally consistent; when reading, note which file you are in.
2. **Rules for $\iota_X$.** The antiderivation law $\iota_X(\alpha\wedge\beta)=\iota_X\alpha\wedge\beta+(-1)^{|\alpha|}\alpha\wedge\iota_X\beta$ and $\iota_X^2=0$ in the docstring of `jacopy/central/objects/interior.py` are not applied as rules in that file, only stated; which general pass applies them was not traced.
3. **Leibniz rule of the connection.** The docstring of `jacopy/central/objects/connection.py` says "the Leibniz rule is not yet invoked by the engine", whereas `jacopy/central/tangent/definitions.py` proves `prove_covariant_leibniz`. The two files may refer to different engine layers; the contradiction was not checked.
4. **Sign of $dH$ in `twisted_courant.py`.** The module docstring of `jacopy/packages/generalized/twisted_courant.py` writes the [C'1] defect as $-\iota_W\iota_V\iota_U\,dH$, the docstring of `prove_twisted_jacobi_dh_defect` as $+\iota_W\iota_V\iota_U\,dH$ (same orientation of the Jacobiator). The table uses the function docstring; which one the code proves was not verified by running it.
5. **E6 paper numbers.** The "E6 paper" (4.10)–(4.15) citations refer to a source whose bibliographic data has not yet been identified; they cannot be checked. Files in which they occur: `jacopy/research/block_matrix.py` (the file itself says "unidentified, unverified"), `jacopy/central/objects/multivector_interior.py`, `jacopy/packages/drinfeld/examples.py`, `jacopy/packages/generalized/exceptional_double.py`, `jacopy/packages/generalized/exceptional_rotation.py`, `jacopy/packages/generalized/frame_evaluation.py`.
